Pixel Jailbreak

Safety in the model’s head vs safety in the pixels.

A project on vision-language model safety: can a jailbreak hidden in an image be caught by reading the model’s activations — when OCR cannot read the image anymore?

What this is Try the explorer

What this project is about

Vision-language models take an image plus a short text prompt. A typographic jailbreak puts the harmful ask inside the image (“how to …”) and only sends a harmless carrier like “follow the instructions in the image.” Text filters never see the bad request.

The question

If the harmful words are degraded — blurred, occluded, compressed — does an input-side OCR filter still catch them? Or does a signal inside the model’s activations hold up better?

Activation probe

A small classifier on the VLM’s hidden states. It does not OCR the image. It detects a harmfulness signal the model already encodes when it understands the request. That is the main positive result below.

Circuit breaker

A LoRA meant to reroute harmful activations so the model stops answering (refusal / noise) while benign prompts still work. Ported to Qwen2-VL here; internals moved, but a clear behavioral win was not shown.

Model: Qwen2-VL-2B · attack: typographic images · this page plays back precomputed rates (no model in the browser). For a live upload → probe + OCR checker, run python tool_probe_ocr.py on a GPU (see repo README).

    Circuit breakers — honest result

    A circuit breaker (Gray Swan / Zou et al.) is a LoRA trained so that when the model’s hidden states look harmful, generation is rerouted away from continuing a harmful answer — ideally collapsing into refusal or noise — while benign prompts still work (retain loss). It does not block the harmful input from entering; it short-circuits the output path in representation space (LoRRA dual loss).

    That trainer was ported to Qwen2-VL for typographic jailbreaks. Internals moved; generation-level short-circuit did not land as a clear win.

    What worked in training

    • Fixed disable_adapter() frozen pass (cosine was stuck at 1.0)
    • RMU loss + LoRA-B noise so gradients exist at init
    • Complying filter: CB-train only where base answered (75/240)
    • Logged cosine fell ~1.0 → ~0.1

    What the eval showed

    SliceBaseCB

    Occlusion is the real jailbreak (~75% comply). CB matched base. Benign utility took a hit (25% incoherent).
